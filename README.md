# coffee.app
自分だけのコーヒー豆の購入記録（ログ）を作成し、蓄積されたデータから自分の好みの傾向を分析・おすすめの豆を提案してくれるWebアプリケーションです。
# サービスの概要
このアプリは、日々のコーヒー体験を記録し、可視化することを目的としています。

コーヒーログ管理: 購入した豆や店舗の名前などの情報、焙煎度・味わい（酸味・苦味・コク・香り）を5段階で詳細に記録。

店舗マップ連携: Google Maps APIと連携し、購入した店舗の場所を地図上で確認。

好み分析・レコメンド:

過去の登録データから、あなたの好みの平均値を算出。

ユークリッド距離を用いたアルゴリズムにより、マスタデータ（17種類の代表的な豆）の中から、あなたの好みに最も近い豆を自動でおすすめします。



# セットアップ方法
1. リポジトリのクローン
   
    リポジトリ内のファイルをダウンロードします
  
2. Google APIキーの設定
   
   メインのPythonファイル内の GOOGLE_API_KEY 変数に、ご自身のGoogle Cloud Platformで発行したAPIキーを入力してください。

    注意: Geocoding API と Maps JavaScript API を有効にする必要があります。
   
    変更必要ファイル

       ・coffee_app.py
       ・upload_coffee_map.html
       ・upload_coffee_input.htm

4. データベースの初期化


   アプリを起動する前に、マスタデータの取得とユーザー用テーブルを作成する必要があります。

   ①まず、豆のマスタデータを取得します。
      
   bean_master.pyを実行し、ブラウザで http://localhost:8782/blist/bean にアクセスして初期化を完了させます。
      
   ②次に、メインアプリの初期設定を行います。
      
   coffee_app.pyを実行し、ブラウザで http://localhost:8782/blist/init にアクセスしてユーザー・店舗・豆管理用のテーブルを作成します。
  
4. アプリケーションの起動
   起動後、 http://localhost:8782/blist/login へアクセスしてください。

# 工夫した点

1. 自分の好み」を数値で見える化する分析機能
   
   既存のコーヒー管理アプリの多くは「備忘録」に留まっており、「次に何を試すべきか」というユーザーの意思決定を支援する機能が不足している点に着目しました。

   課題解決: ユーザーが感じた「酸味・苦味・コク・香り」の評価をデータとして蓄積し、それらの平均値を計算することで、頭の中にある「理想の味」を数値として可視化しました。

   仕組みの工夫：「酸味」や「苦味」などの各項目をグラフ上の点として捉え、あらかじめ登録されている17種類の代表的な豆のデータと、自分のデータの「距離」がどれくらい近いかを計算する仕組みを作りました。


   成果: 感覚的な「なんとなく好き」という状態を数字で裏付けることで、ユーザーの潜在的な好みに合致する「次の一杯」を根拠を持って提案できるようになりました。これにより、新しい豆を選ぶ際の失敗を減らし、自分にぴったりの「次の一杯」を見つける楽しみを提供しています。


2.地図を活用した「思い出」と「味」をつなげる仕組み
  
  「どこでそのコーヒーを買ったか」という場所の記憶は、味の記憶と深く結びついています。単に住所を文字で記録するだけでなく、地図を見るだけで当時の記憶が蘇るような工夫をしました。

   自動で地図に表示:
   住所を打ち込むだけで、システムが自動的にその場所の正確な位置（緯度・経度）を計算して、地図上にピンを立ててくれる仕組みを作りました。これにより、手動で細かい設定をする手間を省いています。

   ピンをクリックして履歴を確認: 地図上のピンをクリックすると、クリック時にその店舗で購入した過去の豆リストを即座に参照できる機能を構築しました。

   こだわり: 「店舗詳細 → 購入履歴 → 各豆の評価」という動線をシームレスに繋ぐことで、地図からすぐにお店の履歴、そして一つひとつの豆の詳しい評価へとスムーズにたどり着けるようにしました。記録を振り返る楽しさを大切にし、直感的に操作できるデザインを目指しました。



# 今後の改善案
  • マップ画面からの店舗登録機能

  現状: 記録入力フォームからの住所入力による登録を主としています。
  
  計画: 地図上の任意地点を選択することで、位置情報から店舗情報を自動取得・登録できる機能を実装します。
 
  • おすすめ機能の改善

  現状: 事前に定義されたマスターデータに基づき、味覚の適合度を算出しています。
  
  計画：今後は自分一人のデータだけでなく、他のユーザーが投稿した評価や感想を共有し、お互いの記録を参考にできる仕組みを導入します。他のユーザーが「美味しい」と感じた豆の情報を自分の分析にも取り入れることで、より自分好みの豆を見つけやすくします。
   さらに、これらの情報を現在地周辺の店舗データと結びつけることで、「今いる場所の近くで、自分や他のユーザーがおすすめする一杯」をすぐに見つけられるような、実用性の高い共有サービスの実現を目指します。
  
  • 画像管理システムの最適化

  現状: 外部URLの参照による画像表示を採用しています。
  
  計画: サーバーまたはクラウドストレージへの直接アップロード機能を実装します。画像をデータとして適切に管理することで、オフライン環境下での参照性を高め、視覚的な記録としての信頼性と一覧性を向上させます。
